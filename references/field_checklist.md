# 贸易单据审查 — 标准字段清单与容差/风险规则

本文件供审单时逐项对齐使用。所有审查必须标注来源与口径（合同值 / 草稿件值 / 官方登记值）。

## 一、适用输入

- 基准：一份销售合同（Sales Contract）。
- 草稿件（待审）：发票 Invoice、装箱单 Packing List、重量质量证 Weight & Quality Cert、提单 B/L、原产地证 COO、植检证 Phytosanitary（可能未出）、中文标签（进口货物）。
- 可选：另一份已签合同单据，用于横向抓"抄错 / 串单"。

## 二、合同 vs 草稿件 逐字段对照（默认字段）

| 字段 | 易错点 | 状态判定 |
|---|---|---|
| 合同号 | 全部草稿件 Exporter Reference 须一致 | ok=一致 |
| 卖方 | 名称+地址须各单据一致 | ok=一致 |
| 买方 | 名称+统一社会信用代码（可补） | ok=一致 |
| 品名 | 是否含 WHOLE/SPLIT、GRADE 描述、等级修饰词 | ok=一致 |
| 规格 | 纯度/等级，注意合同缩写（如 MD P99% 指 Machine Dressed Purity 99%） | warn=草稿件简化漏写 |
| 数量 | 容差核查见第四节 | bad=超容差 |
| 单价 | 币种+金额 | ok=一致 |
| 总金额 | 数量×单价验算 | warn=随数量差异 |
| 贸易术语 | CNF 与 CFR 自 Incoterms 2010 起统一，不构成矛盾 | ok=一致 |
| 装期 | 离港日须在合同装运月内 | ok=一致 |
| 装港 | 合同赋卖方选港权则合同国境内装港合规 | ok=一致 |
| 卸港 | 须与合同一致 | bad=不符 |
| 包装 | 袋重/材质须一致 | ok=一致 |
| 唛头 | B/L 填 N/M 仅指无特殊唛头，需核实袋面基本唛头 | warn=待核 |
| 定金 | 日期对照合同付款条款截止日；金额按合同约定的比例验算 | bad=逾期/金额差 |
| 尾款 | 按合同约定比例验算 | ok=一致 |
| 银行信息 | SWIFT/账号须一致 | bad=不符 |
| 保险 | CFR/CNF 与 FOB 下买方自办正常 | note=买方自办 |
| 单据要求 | 缺项标注（植检证未出、B/L 非正本等） | warn=缺项 |
| B/L 形式 | PROFORMA/DRAFT/占位 Booking No 一律非正本 | warn=非正本 |
| 船名航次 | 合同未指定则无矛盾 | ok=不適用 |
| 船公司 | 合同未指定则无矛盾 | ok=不適用 |
| 集装箱 | 柜数×袋数×袋重=总重验算 | ok=一致 |
| HS Code | 在 COO 体现，须与品名匹配 | ok=正确 |
| COO 形式 | 自贸协定原产地证或一般原产地证，须与合同要求一致 | ok=合理 |
| Producer 注册号 | 走 GACC 系统核验，见 `gacc_registry.md` | ok=系统核验通过 |
| 签发机构 | 商会/签发机构是否具备出证资格 | ok=合理 |
| 中英文标签 | 见 `bilingual_labels.md` | ok=一致 |

## 三、横向串单核查（抓"抄错 / 串单"）

逐一比对以下字段，确认草稿件未误用参考合同的数值：

Exporter Reference（合同号）、卖方、买方、品名、HS Code、数量、单价、总金额、贸易术语、装港、卸港、船公司、船名航次、B/L No、离港日、集装箱公司前缀、Producer、Producer 注册号、COO 备注、签发机构、银行账户、发票序号格式、重量质量证签发地、植检证与 COO 证书号、定金金额、中文标签批号。

判定：字段正确采用本单独立值 → 无串单；误用他单数值 → 串单风险（bad）。

## 四、容差与风险判定规则

- **数量容差**：合同未另作约定时默认 ±5%（允许区间 = 合同量 × 0.95 ~ × 1.05），超出即超标(bad)。若合同写明其他容差（如 ±10% 或"以信用证为准"），以合同为准，并在报告中注明采用口径。
- **定金日期**：对照合同付款条款截止日，晚于即逾期(bad)。
- **定金金额**：按合同约定的比例验算。与发票标注存在差额时，即便金额很小也标 P2 提示，由业务方确认是否属卖方内部取整惯例。
- **B/L 形式**：标注 PROFORMA / DRAFT / 占位 Booking No 一律视为非正本(warn)；仅 FULL SET OF ORIGINAL 可作交单与清关。
- **COO Producer 注册号**：以 GACC 系统核验为准，规则与处置见 `gacc_registry.md`。核验须覆盖号码存在性、注册状态、企业名称、产品范围、有效期、原产国六个维度，仅凭号码格式肉眼判断不可靠。
- **术语**：CNF = CFR（Incoterms 2010 起统一），不构成矛盾。
- **唛头**：B/L 填 N/M 仅指无特殊唛头，需核实袋面是否印有合同要求的基本唛头(warn)。
- **装港**：合同若赋卖方选港权，草稿件装港在合同国境内即合规。

## 五、状态色标（对应 build_report.py 的 level）

- `ok` 一致（绿）
- `warn` 待核/中度（黄橙）
- `bad` 超标/重大（红）
- `note` 注释/买方自办（蓝）
- `pending` 未核验/待补（灰）

## 六、HS 编码

HS 编码须由用户按本次商品提供，或依据合同中已列明的编码。审查时只做一致性比对（COO、发票、报关口径、中文标签四处是否一致），不替用户推断归类。

若需判断编码与品名是否匹配，以目的国海关公开的税则条文为准，并在报告中标注依据来源与查询日期。

## 七、输出规范

- 报告一律 HTML（.html），内联 CSS + 彩色表格，禁止纯文字 MD。
- 编码 UTF-8 BOM，保证双击直接渲染。
- 交付位置由用户指定，或由 `bootstrap.py` 探测到的下载目录，不写死路径。
- 渲染 PNG 留档工作区，便于追溯与复核。
- 关键进度须打印出来，便于用户掌握执行到哪一步。

## 八、部分单据缺失时的处理

实操中草稿件往往不全。按下表处理，不得因缺项中断整个审查：

| 情况 | 处理 |
|---|---|
| 只有合同与发票 | 只做可比对字段，其余标 pending，结论注明"审查范围受限" |
| 植检证未出 | 标 pending，在建议中列出出证后须补核的字段 |
| B/L 为 PROFORMA | 标 warn，仍比对船名航次与集装箱，结论注明正本待换 |
| 无参考合同 | 跳过横向串单核查，报告中注明未做该项 |
| 无中文标签（出口业务） | 中英文标签章节只核对单据内中英字段，不做中文标签合规要素检查 |
| 图片整体模糊 | 提高 DPI 对该页重渲染一次；仍读不清则标"待核"，禁止臆测 |
